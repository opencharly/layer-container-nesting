# 2026.247.0157 — fix: pre-pull alpine at build time so nested-podman-run needs no runtime DNS

## Summary

The `nested-podman-run` check in the container-nesting candy pulled `quay.io/libpod/alpine:latest` at runtime. On hosts where the outer container's aardvark-dns cannot resolve quay.io (a host DNS condition), the pull fails and the check FAILs — blocking the openclaw-desktop bed's `check-live` step.

This PR pre-pulls the alpine image into the nested store at build time (the build container has working network) and changes the runtime check to `--pull=never`, so the check needs no network at runtime.
