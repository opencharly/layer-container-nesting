# 2026.293.1724 — fix(nesting): fetch the smoke image at build time, materialise it at deploy (the sandbox boundary)

## Summary

Head `e49d7e736cc23b136ab8d0995e950a06bb42899e`.

The build-time pre-pull cannot populate the nested store on a sandboxed BuildKit worker: the sandbox denies `unshare(CLONE_NEWUSER)`, so `podman pull` dies at startup with `Error determining cgroups mode` and `skopeo copy … containers-storage:` dies with `Error during unshare(CLONE_NEWUSER): Operation not permitted`. Any box building this candy fails that step (charly#991 — the `distro-cachyos` `box/crabbox-e2e` build died there twice).

The candy now splits the work:

| phase | step | command |
|---|---|---|
| build (root) | the fetch | `mkdir -p /usr/share/charly/nesting-smoke && skopeo copy docker://quay.io/libpod/alpine:latest dir:/usr/share/charly/nesting-smoke` — a pure image fetch needs no user namespace, so it runs on the sandboxed worker |
| build check | `nesting-smoke-layout` | `file: /usr/share/charly/nesting-smoke/manifest.json` exists |
| deploy (`${USER}`, `context: [runtime]`) | `nesting-smoke-materialise` | `skopeo copy dir:/usr/share/charly/nesting-smoke containers-storage:quay.io/libpod/alpine:latest` — the container's own user namespace is available there |

The runtime copy has no network dependency (the bytes are baked), so a host whose outer container cannot resolve `quay.io` still gets a warm nested store, and `nested-podman-run` (`podman run --pull=never`) passes.

The skill (`.agents/skills/container-nesting/SKILL.md`) gains a "Build-time store population (the sandbox boundary)" section with this RCA and the fetch/materialise table; its `/tmp` section now records that the old pre-pull was the trigger and is retired.
